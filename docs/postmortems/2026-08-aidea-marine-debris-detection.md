## 1. 賽事機制(零背景讀者從這裡開始)

### 1.1 這是什麼比賽

**2026 海廢影像辨識國際 AI 競賽**(International Marine Debris Image AI Recognition
Challenge):由 DIGITIMES 與國家海洋研究院、工研院合辦,AWS 技術支持,海洋委員會指導,
於工研院的 **AIdea 人工智慧共創平台**進行。賽事分**初賽、複賽**兩階段(本報告涵蓋初賽全程):
報名 07/08–08/10 → 初賽上傳期至台灣時間 **09-01 23:59:59** → 09-03 公告晉級名單 →
複賽至 09/20。共 **57 隊**參賽。全體隊員須全程出席各階段技術工作坊,缺席即喪失資格。

### 1.2 任務與評分

- **任務**:對海洋廢棄物照片做**物件偵測**——找出每張圖中的海廢(寶特瓶、漁網、浮球、
  塑膠袋…共 **34 個類別**),輸出邊界框+類別+信心分數。
- **評分**:**mAP@0.5**(IoU 門檻 0.5 的 mean Average Precision,34 類平均;平台以
  pycocotools 計算)🅐。官方 baseline(YOLO 系)= **0.623** 供參照;我方最終 0.7916(public)。
- **提交格式**:CSV,每列 `image_filename, label_id, x, y, w, h, confidence`
  (原圖像素座標),每圖上限 **300** 框。

### 1.4 上傳、排行榜與晉級(形塑一切策略的三條規則)

1. **配額**:每隊每「台灣日曆日」**3 次**上傳、不累積(= EDT 前一日 12:00 起算)🅐。
2. **榜規則**:排行榜永遠只掛**最後一次**上傳的成績;分數並列時先傳者在前 🅐。
3. **雙榜制**:比賽期間你只看得到 **Public Leaderboard**(test 的一半);最終名次以
   **Private Leaderboard**(另一半)為準,賽後才公佈。
4. **晉級 = Private 榜前 10 名且 mAP@0.5 ≥ 0.6** 🅐。

三條合起來的策略含義:**最後一發必須是你最好的檔案,而你到最後都不知道它的 private 分**
——整場比賽本質上是在 public 訊號下管理 private 風險(本案的敗因正在此,見 §5)。

### 1.5 合規要求(違者取消資格)

- **34 類紅線**:須直接以原始 34 類訓練,禁止合併/刪減類別。

- **開源揭露**:所用開源資料集與預訓模型須以文件說明來源一併繳回。
- **AWS 環境重現**:須將最終模型+原始碼部署至大會配發的 AWS 環境(每隊 g6.xlarge 等,
  USD 500 點數),主辦依隊伍的 README 執行推論驗證,**無法重現成績即影響晉級與獲獎資格**。
  我方以「位元級重現」策略閉環(§7)。
- 晉級/得獎另須繳模型權重、原始碼、執行說明供驗收;模型授權主辦學術/公益/公務用途。

### 1.6 平台實戰陷阱(公告沒寫、踩過才知道)

- 提交列表顯示 **EDT**、排行榜顯示**台北時間**——同一次上傳在兩處顯示不同日期 🅑,
  是本案四次時區事故的環境根因(§6 #1)。
- **平台只公佈最後一發的 private 分**——賽後無法逐發解剖,private 風險必須在賽中防禦。
- 檔案 mtime ≠ 上傳時間(實測差可達 9 小時)——台帳時刻必須另行記錄。

## 3. 最終配方(檔案級驗證 🅐)

```
12 成員 Weighted Boxes Fusion:
  權重 1.0 × 6:codino_ft(TTA)/ codino_hires(TTA)/ codino one-stage / codino two-stage
               / REG(=S2+S3 class-wise WBF,隊友線)/ S2
  權重 0.5 × 6:ccbb_swin / y12x_r2 / cascade_ms_tta / ccbb_eva02 / s3own / S3
  iou 0.60、skip 0.02(WBF 後砍 conf<0.02 的框)、每圖上限 300
後處理:ConvNeXt-Tiny 信心重排器(rescorer),new_conf = conf × P(crop 為真)^0.1
位元級重現:member_csv 12 檔 → wbf_fuse → apply_rescore → md5 652cb7397ec32a37e2c2b9762f707d54
```

構成分析:Co-DINO 家族(同一預訓權重的四種微調/推論模式)占權重 4/9;隊友 DEIMv2 系
(DINOv2/Swin/EVA02 骨幹)占 3.5/9;異架構(YOLO12-x、Cascade R-CNN)僅 1/9。
**多樣性集中在「推論模式」而非「架構」——這是 private 脆弱性的結構性候選因子之一。**

### 5.3 Private 的背叛與驗屍(2026-09-02 本機計算)

- 16 隊 public→private 位移(源:最終榜 PDF 與 08-31 深夜 public 快照對算):中位數
  **+0.0006**(private 略容易);CCBB **−0.0108,全場最大**;上傳次數與位移相關性弱
  (54 次的隊只掉 0.0035)→ **不是一般性刷榜清算,是我方配方特化**。
- **驗屍 1(skip 軸,無罪)**:量測儀器從 Drive 備份在本機重建成功;Q4b 在 val1868
  (1,868 張、與 282 部分獨立)的 skip 效應複現:0.7020 → 0.7174(+0.0154,當年記錄 t=6.6、
  31/34 類改善;其預登記三診斷兩缺一未達之註記見 §4.3)🅐。skip 是真泛化。
- **驗屍 2(rescorer,主嫌但結構性不可定罪)**:rescorer 是**唯一從未在 val282 以外任何基底
  驗證過的組件**(Q4b 刻意用 pre-rescore 量測);其驗證需要 val 原圖,已隨 EC2 回收——
  **永遠無法補驗**。public 隔離量測 +0.0014;private 貢獻未知,可能為負。
- **驗屍 3(成員選擇效應,共犯嫌疑)**:21 發中至少 5 發是「上傳看 LB → 決定去留」;
  最終配方定義上是「被 public 確認過的路徑集合」。無法分解,但 §5.2 的轉移規律暗示
  調參類增益的 private 存活率最低。
- **歸因結論(誠實版)**:−0.0108 無法分解到單一組件(平台不提供逐發 private 分)。
  結構性證據指向「282 儀器上的調參類增益(rescorer/skip/門檻選擇)+ 成員取捨的 LB 確認迴路」
  的疊加,其中 rescorer 佔比最大但不可證。**σ_p(public↔private 變異)遲至 08-28 才由
  (現已佚失的)split-half 分析粗估為 0.006–0.009(Ⓤ),且從未進入上傳與組件準入決策;
  賽果落在該估計之外約 1.2–1.8σ(Ⓤ)——真正的失敗模式不是「沒估」,是「估太晚且沒用」。**

| 4 | **環境污染** | 1 次 | pip install ultralytics 進量測 venv → numpy/opencv 升版毒殺並行量測 | 每工具鏈獨立 venv;量測 venv 凍結後禁 install |
| 5 | **記憶過期** | 1 次 | 憑 4 天前 memory 催討已到手的 S3 權重 | memory 引用前先對 LOG 最新條目 |
| 6 | **max-of-N 偽增益** | 2 次 | lean5 roster 搜尋 −0.0035;swin36「+0.0066」實為 max-of-12 | 禁 argmax 選擇後直接報數;報 last-vs-last |
| 7 | **台帳失同步** | 2 次 | LEDGER 停在兩版前;5 發從未回填 | 台帳寫入 = 上傳流程的自動步驟,非獨立人工動作 |

## 9. 自動化系統設計藍圖(本報告的最終交付)

依本案提煉的資料流節點與每節點鐵則:

```
[資料進場] → [切分] → [訓練] → [量測] → [門檻判決] → [上傳決策] → [台帳] → [備份/審計]
```

1. **資料進場**:外來資料一律過(a)授權/合規檢查(b)與 test 的重疊稽核(dHash+像素相關)
   (c)座標空間 sanity。產出:LINEAGE 記錄(誰可以用哪個驗證集)。
2. **切分**:**至少兩個互斥驗證集**(本案最大結構教訓)+ 一個凍結 holdout(全程只在最終
   決策前用一次,近似 private)。切分即產出「每個模型的可用驗證集矩陣」。
3. **訓練**:每 run 自動記錄 config/seed/環境快照;checkpoint 自動上雲(權重遺失 = 本案
   四個成員無法重跑的根因);工具鏈 venv 隔離。
4. **量測**:護欄先行(重現已知值否則 ABORT);輸出機器可讀終局行;伺服器端 log 必留檔
   並即時同步(分析型 log 與量測型 log 同等級備份);量測值一律全精度入帳;
   **禁 argmax 後直接報數——涉及多讀數選擇的一律報 last-vs-last 並揭露選擇過程**(§6 #6)。
5. **門檻判決**:門檻以 t 比寫死於預登記,預登記檔案的 birth 時戳即合法性證據;
   **執行回報強制閉環**(預登記發出後 N 小時無結果回報 → 自動標記孤兒並告警);
   判決違規在系統層阻斷(不建檔),不靠自覺。
6. **組件準入**:任何進最終配方的組件須在 ≥2 個互斥基底有正讀數(R4 通則化);
   達不到的組件降權或出局——**對 rescorer 類「自家發明的後處理」尤其嚴格,
   它們是儀器過擬合的頭號宿主**。
7. **上傳決策**:候選檔案 md5 三驗;台帳寫入是上傳流程的原子步驟;榜面回讀自動核對;
   「最後一發 = 最佳檔」由規則(公榜最高分)自動決定;封槍協議含隊友回執;
   **成員/組件的去留判決須過凍結 holdout,不得以單發 public 讀數定案**(驗屍 3 的直接對策);
   配額以狀態機管理(平台雙時區換算程式化,禁人工心算——§6 #1 的配額誤算即其反例)。
8. **備份/審計**:撤離清單由「結論→證據」反向生成;备份完整性以 rclone check 級驗證;
   憑證用後即焚;時戳一律 UTC 程式生成。
9. **機率評估**:σ_p 於**首週**即估——方法:(a)同平台歷史賽事的 public→private 位移分佈
   (b)自建凍結 holdout 對 public 的 split-half 相關(本案 08-28 實際做過,但太晚且未用);
   估出的 σ_p **強制進入**組件準入(調參類增益 < 1σ_p 者不採)與晉級機率計算。
   本案教訓:賽中可得的位移資料有限,寧可用寬 σ_p 保守決策,勝過無 σ_p 的 public 樂觀。
